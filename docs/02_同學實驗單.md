# CH6 小組實驗：讓流程知道何時修正、何時停

**對象：** 會開啟 Python 檔案、修改變數的同學。兩人一組，一人操作、一人先預測再核對結果。

**時間：** 核心 A–C 約 20 分鐘；延伸 D–E 約 10–15 分鐘。環境請在課前完成安裝。

## 開始前

1. 下載 Cyiyang19/agent 的 ZIP 或 git clone，進入含 README.md、setup.cmd 的 agent 專案根目錄。
2. 執行 setup.cmd，確認最後有 PASS。老師的截圖不能代替你自己電腦的執行結果。
3. 打開 demo.cmd，看到選單表示可以開始。
4. 複製本專案 submissions/report_template.md 為你們的報告。

以下指令皆在專案根目錄執行，Windows 使用 PowerShell。若用選單，對照指定號碼即可。

## A. 比較「跑完」與「驗證通過」（5 分鐘）

先預測：原流程只有一筆教材片段，會不會再搜尋？

~~~powershell
.\.venv\Scripts\python.exe -X utf8 -m lab.graph_lab --baseline --output outputs/group_baseline.json
.\.venv\Scripts\python.exe -X utf8 -m lab.graph_lab --output outputs/group_reflection.json
~~~

也可先用選單 1、2 看畫面。記錄：

| 版本 | 搜尋幾次？ | 有哪些來源 ID？ | status | 為什麼停止？ |
|---|---|---|---|---|
| baseline | 自行填寫 | 自行填寫 | 自行填寫 | 自行填寫 |
| reflection | 自行填寫 | 自行填寫 | 自行填寫 | 自行填寫 |

**驗收：** 能在第二份 trace 指出回到 search 的位置，並解釋 baseline 的 unreviewed 為何不是 pass。

## B. 修改條件邊（7 分鐘）

打開 exercises/student_policy.py。它目前一律回 end，是故意留下的練習起點。

完成規則：

- status 是 retry → 回 search。
- status 是 pass 或 needs_help → 回 end。

~~~powershell
.\.venv\Scripts\python.exe -X utf8 scripts/check_exercise.py
~~~

修改前預期會有 FAIL，修改後三項都 PASS。這是學生练習檢查器，與環境的 16 項測試分開；尚未完成練習不代表環境壞了。

**把你的函式接進真的圖：** 打開 lab/graph_lab.py，在既有 route_after_reflection 裡把 return 改成：

~~~python
from exercises.student_policy import choose_next
return choose_next(state['status'])
~~~

兩行放在函式內並保持縮排。再跑：

~~~powershell
.\.venv\Scripts\python.exe -X utf8 -m lab.graph_lab
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
~~~

**驗收：** 搜尋兩次、最後 pass，且測試全數通過。只讓練習檢查器變綠，卻沒把函式接入圖，還不算完成 B。

## C. 修改門檻，先預測再執行（8 分鐘）

打開 lab/settings.py。一次只改一個條件，保留每次輸出。基準值是 MIN_SOURCES = 2、MAX_RETRIES = 1。

| 試驗 | MIN_SOURCES | MAX_RETRIES | 你預測的搜尋次數／status | 真正結果 |
|---|---:|---:|---|---|
| C1 | 1 | 1 | 先填 | 再填 |
| C2 | 2 | 0 | 先填 | 再填 |
| C3 | 3 | 1 | 先填 | 再填 |

每次修改後重跑選單 2，或：

~~~powershell
.\.venv\Scripts\python.exe -X utf8 -m lab.graph_lab
~~~

思考：資料庫只有兩筆，MIN_SOURCES = 3 時，多試十次有幫助嗎？

**驗收：** 請還原基準值 2、1。C3 要能解釋「流程停止是合理結果，不是每一題都必須成功」。

## D. 注入故障並分析（延伸 5 分鐘）

~~~powershell
.\.venv\Scripts\python.exe -X utf8 -m lab.graph_lab --scenario transient
.\.venv\Scripts\python.exe -X utf8 -m lab.graph_lab --scenario failure
.\.venv\Scripts\python.exe -X utf8 -m lab.graph_lab --question "明天台北天氣"
~~~

- transient：只有第一次搜尋故障。
- failure：每次搜尋都故障。
- 天氣問題：不在本地資料支援主題內。

**驗收：** 畫出三者的 trace；解釋為什麼不能拿教材固定資料回答即時天氣。

## E. AutoGen：讓 QA 有真正權力（延伸 5–10 分鐘）

先跑選單 5、6。打開 lab/energy.py，找 buggy_energy 少了哪個單位換算與輸入檢查。

再打開 lab/team_lab.py，找：

1. 誰產生候選實作名稱？
2. 誰真的呼叫 check_candidate？
3. 哪個角色有權用 TERMINATE 結束？
4. 永遠修不好，哪個數值防止無限循環？

修改練習：在 lab/energy.py 的 check_candidate 中新增 (250, 4, 1) 案例，並更新 QA 成功訊息的測試數量描述。不要只改列印文字；要真的加入測試。

**驗收：** buggy 仍被拒絕，fixed 通過；貼上實際 QA 訊息，說明新增測試的用意。

## 小組繳交

- 填妥的 Markdown 報告：組員、環境、實驗前預測、實測表、解釋。
- 修改的 student_policy.py 與 graph_lab.py；若做 E，附 energy.py 與 team_lab.py。
- A 的兩個 JSON 與至少一次完整測試輸出。
- 一句限制：本實驗驗證了什麼，沒有驗證什麼？

建議評分（供本次教學使用，不代表老師正式配分）：環境與證據 20、路由實作 30、參數因果解釋 30、限制與反思 20。

不要繳 .venv、API key 或整本原教材 PDF。使用的外部原始碼須保留歸屬。
