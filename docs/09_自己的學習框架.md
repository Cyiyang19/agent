# 自己的 Agent 學習框架

目標分成兩層：先能獨立解釋與修改 CH6 的課堂實驗，再能做一個有真實模型和工具的簡單 Agent。作業已準備好，不等於已經理解；用能否預測與修改程式來判斷進度。

## 每次學習的固定循環

看一個概念 → 自己畫流程 → 先預測結果 → 執行 → 一次改一個條件 → 用自己的話解釋差異。

每次 35–45 分鐘即可：5 分鐘回想、10 分鐘讀一小段、15–20 分鐘操作、5 分鐘口頭解釋。把未解決問題留下一句，不必把整份資料重新抄成筆記。

## 路線與過關標準

| 階段 | 做什麼 | 使用現成材料 | 能做到才往下 |
|---|---|---|---|
| 1. 認識元件 | 分清模型、工具、狀態、控制流程 | 00_前五章速讀.md、05_最簡單教會你.md | 不看講義，畫出「輸入→決策→工具→觀察→停止」並說出誰真的執行 |
| 2. 跑懂三步流程 | 操作 demo 選項 1、2，逐行看 trace | lab/graph_lab.py | 指出 State、Node、Edge，說明第二次搜尋為何發生 |
| 3. 修改並預測 | 修改門檻 1／2／3、重試上限 0／1 | lab/settings.py、實驗 A–C | 執行前預測 attempts 與 status；錯了能找出哪個假設不對 |
| 4. 理解失敗 | 跑 transient、failure、未知問題 | 實驗 D | 說明工具失敗、沒有資料、預算耗盡的差異 |
| 5. 理解團隊 | 跑 demo 5、6，新增 QA 案例 | lab/team_lab.py、lab/energy.py | 分清角色發言、真正測試、停止條件；知道 Replay 回覆是預先寫好的 |
| 6. 講給別人聽 | 比較四框架，完成自己的 5 分鐘解說 | 01_CH6講義.md、04_講者稿與時間表.md | 能說出改了什麼、為何改、如何驗證，以及此實驗沒證明什麼 |
| 7. 接真實模型（後續） | 取得可用服務或本機模型後，先只換理解／回答節點 | 保留原有控制與測試 | 真實呼叫成功；遇到錯誤能辨識模型、工具或路由問題 |
| 8. 自己做小專題（後續） | 選一個熟悉、可明確驗證的任務 | 可沿用 graph 架構 | 換新輸入仍能解釋結果，且有獨立的驗收案例 |

前六階段不需要 API key。第七階段目前未設定、未驗證，不必為了 CH6 的離線課堂作業先投入額外安裝或費用。

## 這週先安排五次學習

1. 第一次：讀前五章速讀的核心概念，跑選項 1、2，畫三步版和反思版。
2. 第二次：完成學生條件邊練習；逐一改門檻，記下預測與實際差異。
3. 第三次：跑三種失敗情境；解釋為什麼不能一直重試。
4. 第四次：跑 AutoGen 團隊；親手加一個 QA 測試；再比較 AgentScope 與 CAMEL 的設計。
5. 第五次：練 5 分鐘解釋，再排一次 45 分鐘課程。包含同學操作與提問時間，不需要連講 45 分鐘。

如果卡在 Python 語法，只補眼前需要的項目：函式與 return、dict／list、if、import，最後才看 async／await。不要同時學完整 Python、四種框架和模型訓練。

## 每次只留一張短紀錄

~~~text
今天的問題：
我預測會發生什麼：
我改了哪一個地方：
實際結果與證據：
差異的原因：
下一次要查證的一件事：
~~~

建議另存在自己的學習紀錄，尚未理解的內容直接寫「還不懂」。不需要把每次紀錄都公開。

## 怎麼判斷自己會了？

- 能按 demo：只表示會操作。
- 能指出每個步驟的作用：開始理解。
- 能在執行前預測修改的影響：建立了因果模型。
- 能解釋失敗與修正：開始具備除錯能力。
- 能換成自己的題目，設計驗收條件：開始能獨立應用。

例如把來源門檻從 2 改成 3，不只是記住「會 needs_help」，而是說清楚「資料庫只有兩筆，重試不會自動創造第三筆，最後因預算用完停止」。

## 上課前最低標準

能回答以下六題：

1. 什麼是 framework？它幫忙管哪部分？
2. State、Node、Edge 各在程式哪裡？
3. 第一次搜尋為什麼不足？
4. MAX_RETRIES=1 為什麼最多搜兩次？
5. QA 說通過之前，實際做了什麼？
6. 為什麼離線 Replay demo 不能證明 LLM 會自主推理？

這六題比背完四套框架所有類別名稱更適合作為這次報告的學習驗收。
