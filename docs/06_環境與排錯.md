# 環境建立與排錯

## 本次驗證平台

Windows、Python 3.12.14、LangGraph 1.2.11、AutoGen AgentChat／Ext 0.7.4。實際版本與時間見 outputs/environment_report.json。套件安裝在專案內 .venv，不更改其他課程環境。

requirements.txt 是主要直接依賴；requirements-lock.txt 是這次驗證環境的完整固定版本。同學安裝使用 lock，避免自動升版造成行為變化。

## 第一次安裝

有 Python 3.12：雙擊 setup.cmd。沒有：先由 [Python 官網](https://www.python.org/downloads/) 安裝 Python 3.12，勾 Add python.exe to PATH，重開終端後再跑。

setup.ps1 會尋找 py、python，並支援本機 Codex 隨附的 Python。未找到符合版本的執行器時會停止，不把錯誤當成功。

成功需要三層證據：pip check 無破損依賴、pytest 全過、真實 workflow 的結果符合預期。

## 常見狀況

| 現象 | 怎麼處理 |
|---|---|
| 找不到 python | 安裝 3.12 並開新終端；本機可直接用 .venv\Scripts\python.exe |
| No module named langgraph | 先跑 setup.cmd；確認沒有誤用系統的另一個 Python |
| 亂碼 | 使用 -X utf8；以 VS Code／支援中文的終端查看 |
| PowerShell 不允許執行腳本 | 用 setup.cmd；它只在該次程序傳入 ExecutionPolicy Bypass，不永久修改系統政策 |
| 選單 8 有 FAIL | 學生練習尚未完成，照實驗 B 修改；這與環境是否正常無關 |
| needs_help | 看 scenario 與門檻；故障或資料不足實驗的預期結果，不一定是環境問題 |
| pytest 變紅 | 先還原 settings 2／1，查看是否改錯路由；不要只刪測試 |
| recursion limit | 條件邊可能把 needs_help 也送回搜尋，先修判斷 |
| 安裝時網路中斷 | 在有網路時重跑 setup.cmd；實驗執行本身不需外部 API |

## 這台機器的 CET 問題

這次自動化命令啟動器回報「Your Windows doesn't fully support CET」。改由另一個程序啟動方式直接呼叫隨附 Python 與 Git 後，已成功跑完整實驗。這只表示有可用的替代啟動路徑，**不代表 Windows CET 問題已被修復**。

若你自己的終端也遇到相同錯誤，先試一般 Windows PowerShell 或直接執行 .venv\Scripts\python.exe；仍不行再處理 Windows 更新與重開機。以實際 PASS 為準。

## 重新驗證與備援

~~~powershell
.\.venv\Scripts\python.exe -X utf8 scripts/verify_environment.py
~~~

輸出會更新 outputs 下的測試與情境 JSON。上課如果臨時無法執行，可展示已保存的 trace，但須說明它是先前的實測紀錄。

當前目錄外的教材、其他課程檔案與全域 Python 設定都不是本實驗的安裝目標。
