# 前五章：只補 CH6 需要的基礎

閱讀目標：10 分鐘內知道整本書走到哪裡。不必先讀完前五章才開始實驗。

## 先記住一個流程

~~~mermaid
flowchart LR
    Q[使用者給目標] --> M[模型判斷下一步]
    M --> T[工具真的執行動作]
    T --> O[觀察結果]
    O --> M
    M --> A[停止並交付答案]
~~~

這是常見 Agent 的運作模型。模型產生「想做什麼」，工具負責「實際做了什麼」，程式負責「能不能做、什麼時候停」。模型說已經計算或搜尋，不等於工具真的執行過。

本課的離線版把模型換成可預測的測試替身，目的是先看懂整條管線。這種替換就像用已知訊號測試控制器，不是在驗證真實世界所有擾動下的表現。

## CH1：初識智能體（PDF 10–28 頁）

Agent 會根據目標與觀察決定行動。LLM 可以是其中的決策元件；Agent 不等於 LLM，也不一定需要 LLM。

- LLM：根據輸入產生文字或結構化輸出。
- Tool：搜尋、讀檔、計算、呼叫外部服務。
- State／Memory：保存當前任務或歷史資訊。
- Loop：決定下一步與何時結束。

**例子：** 問「1000 W 電器用 2 小時多少度電？」聊天模型可以直接回答；工具型系統會實際呼叫計算函式，取得 2 kWh，再回報。重點是有沒有可追蹤的行動結果。

Workflow 與 Agent 不是完全互斥：有些步驟由程式固定，有些由模型決定。本次 LangGraph demo 是確定性的工作流；接入模型後才能再評估模型決策品質。

## CH2：智能體發展史（PDF 29–49 頁）

理解方向即可：規則／符號推理 → 從資料學習 → 大語言模型與多智能體。這是簡化脈絡，幾種方法仍可共存。

規則法像「如果溫度高於門檻，就開風扇」，結果容易解釋，但規則沒涵蓋的情況會卡住。LLM 對語言較靈活，輸出卻需要另外驗證。**流暢的語句，不等於正確的事實。**

## CH3：大語言模型基礎（PDF 50–75 頁）

只帶走六個詞：

| 詞 | 本課需要的直覺 |
|---|---|
| Token | 模型處理文字的單位；不一定是一個中文字或單字 |
| Context | 本次模型能看到的訊息範圍 |
| Prompt | 給模型的任務、背景、格式與限制 |
| System message | 描述角色與規則的訊息；不保證一定遵守 |
| API | 程式跟模型服務溝通的介面，通常需金鑰與額度 |
| Temperature | 影響取樣隨機性的參數；設低不等於答案必然正確 |

在本次 Replay 模式中，改 system message 不會讓固定回覆變聰明；要改回覆得改測試資料。這是刻意設計的替身。

## CH4：自己寫 Agent 的經典模式（PDF 76–106 頁）

| 模式 | 流程 | 容易遇到的問題 |
|---|---|---|
| ReAct | 判斷 → 行動 → 觀察 → 再判斷 | 工具錯誤、重複行動、不會停 |
| Plan-and-Solve | 先規劃，再逐步執行 | 初始計畫錯了，後續跟著錯 |
| Reflection | 產出 → 評估 → 修正 | 評估不準、反覆修改卻沒進步 |

本次新增 reflect 節點對應 Reflection，但評估者是明確的程式規則，不是另一個 LLM。它只檢查可測量的條件；不會自動保證語意完全正確。

## CH5：低程式碼平台（PDF 107–149 頁）

教材依序使用 Coze、Dify、n8n。把很多流程用 UI 和節點組合起來，能較快做出應用；真正特殊的邏輯仍可能需要程式。先不用辦帳號或學完這三個平台。

從這裡到 CH6 的差別：CH5 主要在平台裡組流程，CH6 用 Python 框架寫流程與協作。
