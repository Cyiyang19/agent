# 你先懂這五件事，就能開始講

## 1. 這份作業到底做什麼？

老師要你把第六章變成一堂「同學聽得懂、而且能動手改程式」的課。你不需要重新訓練大模型，也不是把 PDF 逐頁念完。

你的主題可以直接講：**用框架組織 Agent，並驗證流程與結果。**

## 2. 框架像什麼？

像已經搭好的實驗平台。模型是會提出做法的元件，工具是實際動手的元件，框架把它們的順序、狀態與互動接好。

這個比喻只幫助理解分工；軟體框架不等同硬體平台，也不保證你的演算法正確。

四個名稱先背直覺：

| 名稱 | 先記住 |
|---|---|
| AutoGen | 團隊輪流合作 |
| AgentScope | 管訊息與角色互動 |
| CAMEL | 兩個角色合作完成共同目標 |
| LangGraph | 用流程圖控制下一步 |

## 3. 第一個 demo 在做什麼？

想像同學寫報告：

~~~text
看懂題目 → 找一筆資料 → 寫答案
                         ↓
                  檢查：要求兩筆資料
                         ↓ 不夠
                     再去找一次
                         ↓
                  有兩筆了，結束
~~~

這就是反思回圈。但「反思」在我們程式裡只是明確條件判斷，沒有神祕的意識。

- State：那張共同紀錄表。
- Node：一個工作步驟。
- Edge：下一步往哪走。

**你現在做：** 雙擊 demo.cmd，選 1 再選 2。看兩者搜尋次數差異。

**確認你真的懂：** 如果 MIN_SOURCES 改成 1，要搜幾次？先想，答案在後面。

## 4. 第二個 demo 在做什麼？

~~~text
PM 說需求 → 工程師給候選 → 審查員檢查 → QA 真的跑測試
                                                  ↓
                                             失敗就下一輪
~~~

1000 W 用 2 小時 = 2000 Wh = 2 kWh。buggy 忘記除 1000，QA 會抓到；fixed 修正後才過。

**你現在做：** 選單 5，找 QA_FAIL 與 QA_PASS。

要誠實說明：工程師的兩輪回覆是預先安排的。這次證明框架和 QA 能跑，不是證明 AI 自動修好程式。

## 5. 上台前只練這條路線

1. 用一句話介紹四個框架。
2. 選 1：原版沒有檢查。
3. 選 2：有檢查，所以會重試。
4. 選 4：一直失敗，要停止求助。
5. 選 5：QA 真正測到錯誤，修正版才通過。
6. 請同學修改 student_policy.py 並接回 graph。

能不用看稿說明這六步，再讀完整講義。不要先花一小時背所有 Python 類別名稱。

### 前面自測的答案

MIN_SOURCES = 1 時，第一次拿到一筆已達門檻，所以搜尋一次就 pass。

再想一題：資料庫只有兩筆，要求三筆時，重試很多次會自動生出第三筆嗎？不會。更多計算不會憑空補出不存在的證據。
